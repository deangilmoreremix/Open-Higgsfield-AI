## Superpowers Methodology Application

### Phase 1: Systematic Debugging (Root Cause Analysis)

Follow the 4-phase systematic debugging framework:

#### **Phase 1A: Isolate Symptoms**
- Run `pnpm run build:all` locally to capture exact error
- Document all error messages with file paths and line numbers
- Identify build break points vs. warnings
- Separate runtime issues from build-time failures

**Evidence Collection Tasks:**
```bash
# Capture build output
pnpm run build:all 2>&1 | tee build-errors.log

# Check for missing exports
grep -r "initializeEnhancedMuAPI" src/

# Verify TypeScript compilation
cd netlify/functions && npx tsc --noEmit

# Check environment variable requirements
grep -r "process.env" netlify/functions/*.ts
```

#### **Phase 1B: Trace Conditions**
For each error, create a cause-effect chain:
1. **Missing Export Error**
   - Symptom: `initializeEnhancedMuAPI` not exported
   - Trigger: `src/main.js:14` imports non-existent function
   - Root Cause: `muapiEnhanced.js` lacks initialization function
   - Impact: Build fails immediately (exit code 1)

2. **TypeScript Functions Not Compiled**
   - Symptom: `.ts` files in Netlify functions directory
   - Trigger: Netlify requires JavaScript, not TypeScript
   - Root Cause: `tsconfig.json` has `"noEmit": true`, no build script
   - Impact: Functions fail to deploy or crash at runtime

3. **Package Manager Conflict**
   - Symptom: Mixed pnpm/npm in build command
   - Trigger: `netlify.toml` uses `pnpm install && npm run build:all`
   - Root Cause: npm doesn't respect pnpm workspace linking
   - Impact: Module resolution failures for local packages

#### **Phase 1C: Verify Fixes Before Implementation**
- Create isolated test branches for each fix
- Use git worktrees to parallelize testing:
```bash
# Create separate worktree for each fix
git worktree add -b fix/muapi-export worktrees/muapi-export
git worktree add -b fix/netlify-ts worktrees/netlify-ts
git worktree add -b fix/netlify-config worktrees/netlify-config
```
- Run build in each worktree to verify isolated fix works

#### **Phase 1D: Defense in Depth**
- Add validation for each fix (e.g., ensure function is exported before build)
- Add pre-build checks that fail fast with clear messages
- Document environment variable requirements clearly
- Add build-time guards for missing configurations
