  - netlify/functions/* (director-agent, package.json, tsconfig, handlers)

  - public/apps/remix-go/assets/index-*.js.map (generated asset)
  - src/components/VideoStudio.js
  - src/lib/muapiEnhanced.js

Why cherry-pick is preferred here
- The branch is tiny (3 commits) but very stale (399 commits behind). Rebasing that branch onto main would introduce a large set of unrelated conflicts and is high-risk.
- Cherry-picking isolates the three units of work, allowing manual porting into the current code shape and minimizing unintended regressions.

Detailed step-by-step plan (implementation branch, non-destructive)
1. Create a work branch off current main (no changes to main):
   - git fetch origin
   - git checkout -b work/netlify-fixes origin/main

2. Cherry-pick commits in order:
   - git cherry-pick ac88f0d
   - Resolve conflicts (see file-specific rules below), git add <file>, git cherry-pick --continue
   - Repeat for 89984e4 and d6df36c
   - If a commit cannot be applied cleanly, consider: git cherry-pick --skip (if commit obsolete) or abort and port manually.

3. Conflict-resolution rules (summary):
   - Prefer main's current structure and APIs; port only the functional logic from the stale commits into main's shape.
   - For package.json changes: merge only necessary scripts/deps; do not blindly accept upstream dependency versions.
   - For lockfiles: do not hand-edit; regenerate via pnpm install after package.json is finalized.
   - For deleted-by-main files: accept deletion if main intentionally removed or moved the feature — port logic into new locations rather than restoring deleted artifacts.
   - For Netlify functions: integrate handler source but adapt to main's functions layout (dist vs src). Add a build step if needed.
   - For generated assets (maps): do not commit build artifacts; prefer to add build steps or ignore them.

4. Regenerate lockfile and install dependencies (after resolving package.json):
   - rm -rf node_modules pnpm-lock.yaml package-lock.json
   - pnpm install
   - git add pnpm-lock.yaml package.json
   - git commit -m "chore: regenerate pnpm-lock after netlify fixes"

5. Verification (required before PR):
   - npm run test:typecheck
   - npm run test:lint (or npm run lint)
   - npm run test (unit tests)
   - npm run build (main build) and any app-specific builds touched by netlify functions
   - Optional: run local Netlify dev to smoke test serverless handlers

6. Push work branch and open PR: work/netlify-fixes -> main
   - Include detailed PR description of manual ports and verification checklist.
   - Request CI runs and code review; merge after green.

7. Fallback if cherry-pick is too noisy:
   - Abort cherry-pick and create a fresh branch from main: git checkout -b feat/netlify-fixes-manual origin/main
   - Manually port the small fixes by copying/adapting code from origin/fix/netlify-deployment-blockers into the new branch as clean commits.
   - Test and PR as above.

- Worst case (porting handlers and rebuilding functions, lockfile churn): 3–8+ hours
